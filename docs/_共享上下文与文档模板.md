### 1.3 网络层约定

- 基础域名：`Constants.baseURL = "http://127.0.0.1:4000"`（网关）。
- WebSocket：`Constants.webSocketURL = "ws://127.0.0.1:4000/service/chat/ws/chat"`。
- 所有 HTTP 请求走 `HTTPClient.shared` 上封装好的业务方法，底层统一走
  `HTTPClient.request<T>(endpoint:body:queryItems:completion:)`。
- 接口路径常量集中在 `Constants.API`，枚举与 method 映射在 `APIEndpoint`
  （`APIEndpoint.path` 负责把 `{tenantId}`、`{docId}` 等占位符替换掉，
  `APIEndpoint.method` 声明 GET/POST/PUT/DELETE）。
- 鉴权：`TokenManager.shared` 用 `UserDefaults`（key `auth_token`）存 token，
  请求头 `Authorization: Bearer <token>`；WebSocket 用 `?token=` 查询参数。
  网关解析出 `userId` 后以 `X-User-Id` 透传给下游，**客户端无需传 userId**。
- 统一响应体 `BaseResponse<T>`：

```swift
struct BaseResponse<T: Codable>: Codable {
    let data: T?       // 业务数据
    let token: String? // 仅登录/注册/getUserData 返回
    let status: String // "SUCCESS" / "FAIL"
    let msg: String?   // 失败提示
    let total: Int?    // 仅分页接口返回
    var isSuccess: Bool { status == "SUCCESS" }
}
```
  辅助类型：`EmptyData`（data 为空）、`StringData`（data 为字符串）、`NumberData`（data 为数字）。
- 业务方法签名统一为闭包回调：`(Result<T, NetworkError>) -> Void`，
  UI 层回调内必须 `DispatchQueue.main.async` 切主线程再改 `@State`。

**易错点（已核对源码）**：

- `UserPage` 本身就是个人资料编辑页（PhotosPicker 换头像 + CustomDialog 改昵称/电话/邮箱/性别/生日/地区/签名），并负责退出登录。
- `UserInfoPage` 不是"我的资料"，而是**公司成员详情（只读）**，构造参数 `companyUser: CompanyUser`，只能从 `UserManagePage` 点列表项进入。
- `UserManagePage` 管理的是**公司成员**（`CompanyUser`，→ `AddCompanyUserPage`）；`TenantManagePage` 管理**租户**（→ `AddTenantUserPage`）。别混。

`MainView` 与 `ContentView` 是脚手架占位页，未接入主链路。

## 三、编写规则（硬性）

1. **只写代码里真实存在的东西**。方法名、状态名、常量名、接口路径必须与源码逐字一致。
2. **不编造后端字段**。接口出入参以 `docs/api/<模块>.md` 为准；后端文档没写的，标注「后端文档未覆盖，按客户端解码结构推断」。
3. **发现代码 bug 要记录**在「二次开发指引 → 已知坑」里，不要静默修正。
4. 中文书写，术语（类名/方法名/常量名）保留英文原文。
5. 每份文档 200~450 行；HomePage、UserPage 等复杂页面可到 600 行。
6. 代码片段只贴关键几行，禁止整段复制页面源码。
7. 文档之间用相对链接互引，例如 `[UserPage](UserPage.md)`。
